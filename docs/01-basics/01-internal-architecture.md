# 8086 微处理器内部结构

## 一、概述

Intel 8086 是 Intel 公司于 1978 年推出的 **16 位微处理器**：

- 内部数据总线：16 位（一次可处理 16 位二进制数）
- 外部数据总线：16 位
- 地址总线：20 位，可寻址 **1MB**（2^20 = 1,048,576 字节）内存空间
- 采用 **40 引脚双列直插（DIP）封装**，单一 +5V 电源
- 主频：标准 5MHz（后续有 8086-1/-2 等更高主频版本）

8086 在内部结构上最大的特点是：**取指令和执行指令由两个独立的功能部件并行完成**，即总线接口部件 BIU 与执行部件 EU。

---

## 二、两大功能部件

```text
                    ┌──────────────────────────────┐
                    │           BIU                │
                    │  (Bus Interface Unit)        │
                    │                              │
   地址总线 ◄────── │  段寄存器 / IP / 地址加法器   │ ──────► 存储器
   数据总线 ◄────── │  指令队列(6字节) / 总线控制   │ ◄────── I/O
                    └──────────────┬───────────────┘
                                   │ 内部总线
                    ┌──────────────┴───────────────┐
                    │           EU                 │
                    │  (Execution Unit)            │
                    │                              │
                    │  ALU / 通用寄存器 / 标志寄存器 │
                    │  EU 控制系统                  │
                    └──────────────────────────────┘
```

### 1. 总线接口部件 BIU（Bus Interface Unit）

BIU 负责 CPU 与**存储器、I/O 设备之间的信息传送**，是 CPU 与外部总线的接口。

**组成：**

| 组成部分 | 功能 |
| :--- | :--- |
| 4 个段寄存器 | CS、DS、SS、ES，提供段地址 |
| 指令指针 IP | 存放下一条要取指令的偏移地址 |
| 20 位地址加法器 | 将段地址与偏移地址合成为 20 位物理地址 |
| 指令队列 | 6 字节，预取指令，先进先出（FIFO） |
| 总线控制逻辑 | 产生内存/IO 读写、中断响应等总线控制信号 |

**主要任务：**

1. 从内存中**预取指令**，送入指令队列排队
2. 配合 EU 的请求，从内存或 I/O 端口**取操作数**
3. 将 EU 的运算结果**写回**内存或 I/O 端口
4. 计算并发出 20 位物理地址

### 2. 执行部件 EU（Execution Unit）

EU 负责**指令的译码与执行**，不直接与外部总线相连。

**组成：**

| 组成部分 | 功能 |
| :--- | :--- |
| 算术逻辑单元 ALU | 完成 8/16 位算术与逻辑运算 |
| 8 个 16 位通用寄存器 | AX、BX、CX、DX、SP、BP、SI、DI |
| 标志寄存器 FLAGS | 记录运算结果特征与控制标志 |
| EU 控制电路 | 指令译码、时序控制，向 BIU 发出操作请求 |

**主要任务：**

1. 从指令队列中取出指令并译码
2. 通过 ALU 执行运算，修改寄存器与标志位
3. 需要访问内存/IO 时，向 BIU 发出请求并提供偏移地址

---

## 三、指令流水线（并行工作机制）

8086 之前的 CPU 采用串行方式：取指 → 执行 → 取指 → 执行……总线在执行期间空闲。

8086 的 BIU 与 EU **并行工作**：

- BIU 预先把后续指令从内存取出，填满 6 字节指令队列
- EU 执行当前指令时，BIU 同时在后台取后续指令
- EU 执行指令若需要操作数，向 BIU 申请，由 BIU 完成内存/IO 访问

```text
时间 →
BIU:  取指1  取指2  取指3  取操作数  取指4 ...
EU:         执行1   执行2   执行3(需访存)  执行4 ...
```

**意义：**

- 减少 CPU 等待总线的时间，提高总线利用率与执行速度
- 这是现代 CPU **指令流水线（Pipeline）**思想的早期体现
- 当发生转移（JMP/CALL）时，队列中预取的指令作废，BIU 需从新地址重新取指，因此转移指令会产生性能损失

---

## 四、内存访问的工作过程

当 EU 执行一条需要访问内存的指令时：

1. EU 向 BIU 提供**偏移地址（Offset）**
2. BIU 中的地址加法器将其与对应段寄存器的段地址相加：

```text
物理地址 = 段地址 × 16（即左移 4 位）+ 偏移地址
```

3. BIU 把 20 位物理地址送到地址总线，发出读/写控制信号
4. 通过数据总线完成一个字节或一个字（16 位）的传送

> 一个 16 位的字存放在两个相邻字节单元中：低字节存低地址，高字节存高地址（小端存储，Little-Endian）。

---

## 五、小结

| 要点 | 内容 |
| :--- | :--- |
| CPU 位数 | 16 位，数据总线 16 位，地址总线 20 位 |
| 两大部件 | BIU（取指/访存，含 6 字节队列）与 EU（译码执行，含 ALU） |
| 并行机制 | BIU 取指与 EU 执行并行，构成指令流水线 |
| 地址形成 | 20 位地址加法器：段地址 × 16 + 偏移地址 |
| 字的存储 | 小端方式，低字节在低地址 |
