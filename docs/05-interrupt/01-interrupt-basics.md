# 中断基础

## 一、中断的概念

CPU 在正常执行程序时，由于内部或外部事件，暂时中止当前程序，转去执行处理该事件的**中断服务程序（中断处理子程序）**，处理完后再返回原程序继续执行，这一过程称为中断。

中断机制使 CPU 能：

- 及时响应外部设备请求（如键盘、定时器）
- 实现多任务与实时处理
- 处理异常（如除法错、溢出）

---

## 二、中断源分类

### 1. 按来源

| 大类 | 说明 |
| :--- | :--- |
| 硬件中断（外部中断） | 由 CPU 外部引脚信号触发 |
| 软件中断（内部中断） | 由 INT 指令或异常产生 |

### 2. 硬件中断

| 中断 | 引脚 | 特点 |
| :--- | :--- | :--- |
| 非屏蔽中断 NMI | NMI | 不受 IF 控制，用于紧急故障（如内存奇偶错） |
| 可屏蔽中断 INTR | INTR | 受 IF 控制：IF=1 响应，IF=0 屏蔽；经 8259A 管理 |

### 3. 软件中断（内部中断）

| 类型 | 触发 |
| :--- | :--- |
| 除法错中断 | 类型 0，除法溢出或除以 0 |
| 单步中断 | 类型 1，TF=1 时每条指令后触发 |
| 断点中断 | 类型 3，调试用 |
| 溢出中断 | 类型 4，INTO 且 OF=1 |
| INT n 指令 | 用户指定类型号 n |

内部中断特点：**不受 IF 影响，无中断响应总线周期**。

---

## 三、中断响应过程

可屏蔽中断的完整过程：

1. **中断请求**：设备向 8259A 发请求
2. **中断判优**：8259A 比较优先级，向 CPU INTR 发信号
3. **中断响应**：若 IF=1，当前指令执行完后，CPU 发出两个 INTA 负脉冲
4. **保护断点**：FLAGS、CS、IP 依次压栈；清 IF、TF
5. **读取类型号**：第二个 INTA 周期，8259A 把中断类型号送上数据总线
6. **转入服务**：根据类型号查向量表，得到中断服务程序入口并跳转
7. **中断返回**：服务程序末尾用 IRET 弹出 IP、CS、FLAGS

```text
PUSH FLAGS
PUSH CS
PUSH IP
IF ← 0, TF ← 0
查向量表 → CS:IP = 服务程序入口
...
IRET
```

---

## 四、中断优先级与中断嵌套

### 优先级（从高到低）

```text
内部中断（除单步） > NMI > INTR（可屏蔽） > 单步中断
```

### 中断嵌套

高优先级中断可打断正在执行的低优先级服务程序。要实现嵌套，需在服务程序中用 STI 重新开中断（IF=1）。

---

## 五、中断返回指令 IRET

```text
IRET        ; 依次弹出 IP、CS、FLAGS
```

与 RET 的区别：IRET 多恢复了标志寄存器，保证被中断程序的状态完全还原。

---

## 六、小结

- 中断分硬件（NMI/INTR）与软件（内部异常/INT n）
- 响应过程：请求→判优→响应→保护断点→取类型号→查向量表→服务→IRET
- 内部中断与 NMI 不受 IF 控制，INTR 受 IF 控制
- 优先级：内部中断 > NMI > INTR > 单步
